# 保護資訊與場景處理

## 改稿前後的資訊核對

先在內部記下以下內容，完成後逐項核對。清單不用出現在成稿。

| 類別 | 要保住的內容 | 常見漂移 |
| --- | --- | --- |
| 數字 | 數值、單位、幣別、約數、上下限、比較基準 | 「最多 26 人」變「26 人起」，「約 3 小時」變成確定 3 小時 |
| 時間 | 日期、截止時間、時區、先後次序 | 「申請截止」變「付款截止」 |
| 行動 | 讀者做什麼、在哪裡做、完成後得到什麼 | 刪掉付款或候補步驟 |
| 條件 | 適用對象、限制、例外、否定 | 「不含錄影」變成「可回看」 |
| 原字串 | URL、價格表示、逐字引語、代碼、正式名稱 | 修改參數、替引語換詞、改產品拼法 |
| 立場 | 作者選擇、批評對象、理由、確定程度 | 尖銳批評被修成空泛中立 |
| 證據 | 引語歸屬、資料出處、已知與假設的界線 | 引語變作者斷言，示例變真實成果 |

保護意思與資訊，不要求所有一般句子字面相同。使用者明確授權更正時才改受保護資料，有疑問就處理那個具體疑問。

## 場景決定寫法

| 場景 | 先交代 | 保留的語氣與內容 |
| --- | --- | --- |
| 社群觀點 | 作者主張、觸發事件 | 取捨、自然情緒、具體例子，有作用的短句可留 |
| 案例長文 | 人物、問題、選擇 | 成長過程、場景、推理，不要把先後硬接成因果 |
| 教學 | 要完成的工作 | 步驟順序、判斷方式、必要條件與例子 |
| 課程／活動 | 對象、內容、時間、報名方式 | 名額、價格、候補、付款與取消規則 |
| 商務／內部通知 | 變更、負責人、期限 | 承諾、附件、交付範圍，禮貌可以簡短 |
| 客服 | 問題、處理結果或下一步 | 合理道歉、同理、責任，保留尚未完成的狀態 |
| 銷售 | 需求與產品實際能力 | 有證據的優點、CTA、適用條件，不加不存在的案例與保證 |

例如，客服可以寫「讓你等了三天，抱歉。我們今天會寄出補件。」前提是三天與今天寄出都已確認。沒有出貨承諾時，改寫時沿用已知處理進度，不自行承諾今天。

## 台灣用詞與標點

用符合語境的台灣繁中。談檔案操作可用「儲存」，談商業產品可用「品質」，物理量「質量」、幾何方向「水平」保留。不要建立無條件取代字典。

依作者已確認的偏好使用標點。林思翰把相連句意用逗號接起來，句意完成才加句號，例如「雨停了，我還坐在騎樓下，不想回去。」其他作者則依其範例判斷，不套用同一種停頓。品牌、英文句子、URL、數學式與程式碼保留原格式。不要為了全形化破壞可複製的指令。

## 三個應保留的例子

1. 「我把簡報重做了三次，最後只留一張圖。客戶在那張圖停了十分鐘。」如果是作者提供的真實經歷，直接保留場景，不能改成未提供的成交成果。
2. 「不是價格太高，是我們一直沒說清楚包含哪些服務。」這個對比區分兩個問題，有資訊價值，可以留。
3. 「雨停了，我還坐在騎樓下，不想回去。」敘事與情緒已經完整，保留逗號，不補人生感悟。

## 收到回饋時

使用者說「還是太 AI」時，找出具體原因：主張重複、內容抽象、節奏整齊、假感想、條件補句，或作者立場被磨平。修正那個問題，不只換同義詞。

使用者說「刪太多」時，回到素材與要求，補回被刪的資訊、故事作用或推理。不要用另一段感想補字數。
