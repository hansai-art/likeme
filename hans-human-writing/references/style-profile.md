# 林思翰的寫法基準

這份資料描述的是穩定的寫作判斷，不是要求每篇文章都模仿同一批口頭禪。技能要複製的是「怎麼選內容、怎麼下判斷、怎麼把事情說清楚」，不是把樣本裡的句子換個主題再貼一次。

## 核心順序

林思翰的成品通常先回答「所以呢？」再補理由與做法：

1. 先給判斷、事件或結果。
2. 說明這個判斷根據什麼。
3. 放入必要的數字、案例、條件或限制。
4. 給讀者下一步，或收在一個有內容的結論。

這個順序適合回答問題、寫教學、分析方案與商務通知；品牌貼文或故事文章可以調整節奏，但不能用氣氛取代主張。

## 語氣訊號

### 保留

- 直接講人、事、時間、差異與選擇。
- 作者有明確判斷時，把「我會選哪個」和理由寫出來。
- 有畫面的生活例子、稍微口語的動詞、自然的反差與必要的幽默。
- 為了讓對方看懂而補一個具體假設或場景。
- 遇到限制時，寫限制如何影響做法，不用一整段免責。

### 刪除或避免

- 「好問題」「當然可以」「希望對你有幫助」等沒有資訊的開場與收尾。
- 「在這個快速變動的時代」「值得一提的是」「總而言之」等沒有內容的過場。
- 「不一定」「視情況而定」「僅供參考」等沒有說出實際條件的防守句。
- 每段都用同樣長度、同樣句型、同樣小標，讓文章像模板。
- 用抽象名詞替代事件，例如「做出重要決策」「創造全新體驗」「實現價值」。
- 用粗話、錯字、故意不完整句子或假裝隨意的語氣製造人味。

## 標點與節奏

相連的動作、畫面與情緒，用逗號接起來，意思完成再用句號：

> 雨停了，我還坐在騎樓下，不想回去。

句意真的換方向才分段。不要把每一個短句拆成一行，也不要因為看起來整齊就把有畫面的例子合併成分類摘要。

列舉同類項目正常用「、」。分號只在兩個完整且需要並列的句意確實分開時使用，不能拿來製造正式感。

## 具體比抽象有效

| 空泛寫法 | 直接寫法 |
| --- | --- |
| 這次更新帶來更好的使用體驗。 | 這次更新新增 CSV 匯入，匯入後先預覽，確認後才寫入名單。 |
| 團隊做了一個後來很成功的決定。 | 團隊取消原本的用途限制，開放其他內容上傳。 |
| 這個流程能大幅提升效率，但仍需視情況而定。 | 這個流程省掉人工分類，能減少整理步驟；尚未計時就不補節省比例。 |
| 我們會積極處理，請放心。 | 我們正在確認補件庫存，明天下午 3 點前回覆結果，寄出時間確認後再通知。 |
| 這篇文章對產品、工作與人生都有啟發。 | 先看使用者實際拿產品做什麼，再決定要改定位，還是補一個更合用的入口。 |

最後一組不是固定金句。要依素材是否真的支持這個判斷，不能為了像作者而擴大主張。

## 「像我」不是什麼

不要把作者樣本中的品牌、客戶、學生、職稱、經歷或情緒搬到新文章。不要把「有作者判斷」誤解成每段都要加「我認為」。作者的判斷可以透過取捨、順序、例子與結論呈現。

不要把「去 AI 味」誤解成：

- 每句都換同義詞。
- 把「狗」「奇怪的零食」換成「寵物」「日常生活」。
- 把原本的段落壓成摘要。
- 故意加入口頭禪、錯字、粗話或不完整句子。
- 每段都加一個反問、對比或人生體悟。

## 輸出樣式

預設輸出完整成稿，不輸出「我做了哪些修改」。如果要求分析，先給判斷，再列具體問題與替代寫法；如果要求前後對比，對比真正有改動的句子，不要為了湊數把保留句也列成修改。
