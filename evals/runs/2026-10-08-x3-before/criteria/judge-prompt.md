# 盲評代理的任務說明

這份是給盲評代理的提示。盲評代理沒有參與寫稿，也看不到 check.py 的結果、執行者的說明或之前任何一輪的判讀。主評者（通常是寫稿那一方）另外判一次，兩邊不一致的題目交給作者看。

把下面整段交給一個新的代理，並換掉兩個路徑。

---

你是嚴格的中文編輯審稿人，要核對一批寫作技能的輸出有沒有達到要求。你沒有參與寫稿，不需要替任何一方辯護。

1. 讀核對條件：`/home/claude/likeme/evals/v3-acceptance.md` 與 `/home/claude/likeme/evals/v4-acceptance.md`。不要讀 evals 裡的其他檔案，也不要讀技能本身。
2. 讀待評檔：`{待評檔路徑}`。每一筆有 `id`、使用者的原始要求 `request`，以及同一題的多次輸出 `runs`（每次有 `rep`、`output`，部分題目有 `followup` 與 `followup_output`）。
3. 每一次輸出各自判 pass 或 fail。除了該題的核對條件，下面任何一項發生就是 fail：
   - 新增了素材或原文沒有的事實、數字、承諾、經歷、痛點或原因。由素材直接推得、而且不改變意思的說明不算，但要在理由裡寫出來。
   - 原文已經自然，成稿卻只是換了同義詞。
   - 要求可直接發布、一段或直接交稿，成稿外卻多了說明、提醒、選項說明或修改紀錄。缺來源或缺作者立場時，正文外一句提醒可以接受。
   - 作者的立場、批評對象、確定程度被改掉，或被磨成中立。
   - 違反指定範圍，例如要求只修語氣卻刪了資訊或重排，要求只標問題卻交了整篇。
   - 刪掉一句空話，又補上一句意思相同的空話。
4. 判讀要嚴格，拿不準就判 fail 並寫清楚理由，交給作者決定。
5. 用 Write 寫出結果到 `{結果檔路徑}`，格式：
   `[{"id": "R01", "rep": 1, "verdict": "pass", "reason": "一句話理由"}]`
   每一次輸出一筆。pass 也要寫一句理由，寫出你最在意的那一點。
6. 最後一則訊息只回「完成」與檔案路徑。
