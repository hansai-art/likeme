# 設計筆記與參考來源

## 從 YouTube 案例出發

這個技能從林思翰提供的 YouTube 起源文章與改稿回饋出發，處理重複主張、戲劇預告、碎句、抽象評語、假作者感想與預防性補句，每項規則都要接上正向做法，再用原文示範。

研究 Raymond Hou 的 [speak-human-tw](https://github.com/Raymondhou0917/speak-human-tw) 後，補強了資訊保護、依場景調整，以及驗證哪些文章應該保持原樣，讀取版本為 [eeb527d](https://github.com/Raymondhou0917/speak-human-tw/tree/eeb527d273905bc3c38d479f8dab8522114a157a)，研究日期為 2026-10-02。

像我本人先判斷句子要留、刪或改，沒有作用的內容直接刪，必要資訊才改寫。

## 本版本的具體做法

| 設計選擇 | 執行方式 |
| --- | --- |
| 刪除與改寫 | 沒有作用就直接刪，有必要資訊才改寫，不為每句廢話安排替代句 |
| 觀察旁白 | 直接寫團隊的選擇，省掉「我會看」與「這篇文章交代的是」 |
| 預防性補句 | 推論程度放回原句，必要限制改成行動條件 |
| 作者聲音 | 保留立場、選擇與理由，依本人樣本與當次回饋判斷用字、節奏與標點 |
| 標點 | 林思翰的相連句意用逗號，說完才加句號，範例為「雨停了，我還坐在騎樓下，不想回去。」 |
| 對比句 | 檢查它區分的問題是否真實，判斷是否有根據，有作用的正常對比保留 |
| 新寫與改稿 | 支援從素材完成文章，以及直接改稿、微調、診斷、對比 |
| 資訊保護 | 核對數值、單位、約數、上下限、否定、承諾、URL、引語、立場與出處 |
| 來源缺口 | 查核具體缺口，保留歸屬，不把「研究指出」刪成已確認的事實 |
| 格式保護 | 程式碼、指令、資料欄位與有效引用預設保留，只改授權的文案 |
| 長文 | 保留必要場景與推理，尊重不刪內容與指定篇幅 |
| 正反例 | 12 組中有 8 組節錄 YouTube 原文，逐項提供保留、刪除或改寫的方法 |
| 誤改檢查 | 測正常對比、自然敘事、專業術語、具體提醒與清楚通知 |

維基百科頁面是社群對寫作痕跡的觀察，這裡用作編輯參考，LikeMe 的驗收看資訊、原意與閱讀效果，沒有用句型命中數推算「AI 含量」。

## 怎麼整合參考資料？

「不是價格太高，是我們一直沒說清楚包含哪些服務」能區分兩種問題，可以留，若整篇連續把各種事情都改成「不是 X，是 Y」，先看 X 是否真有人主張，再看 Y 有沒有根據，最後才調整節奏。

參考資料提供不同的編輯觀點，整合時先看資訊與作者意圖，再決定刪改範圍，處理表達後回查原文。無效句子可以直接刪，原本清楚的句子可以保留，沒有必要替每段補一個新道理。

## 怎麼驗證？

技能格式驗證確認名稱、描述與 YAML 格式，初次寫作驗證以兩個新執行緒完成 12 題，執行者只收到技能與原始任務，課程數字更新後，R01 另用新執行緒執行；標點更新後，P02 也另行執行，其他題目保留 2.0.0 初次輸出，2.1.0 的重跑範圍為 P02，2.2.0 另用新執行緒完成 R07、P06，核對無效句刪除與自然文字保留，主編再人工核對。

[題目](../evals/prompts.json)、[輸出](../evals/outputs.json) 與 [結果](../evals/results.md) 分開公開，方便重跑，目前累積 14 個任務，沒有對照組或其他技能比較，後續要增加完整長文與多輪改稿。
