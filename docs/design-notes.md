# LikeMe 設計筆記與研究來源

## 這個技能要做什麼

LikeMe 不是通用的「人味改寫器」，也不是 AI 禁詞表。它要處理的是林思翰常遇到的幾種工作：

- 根據素材寫出有作者判斷的台灣繁中文章與社群貼文。
- 把品牌文案、課程公告、商務通知、客服回覆與教學寫清楚。
- 修改文章時保留事實、作者立場、具體場景與必要條件。
- 去掉重複鋪陳、抽象評語與空泛免責句，但不把自然原文全部重寫。
- 在資訊不足時指出具體缺口，不用虛構數字、成果、經歷或承諾補空白。

## 從產品起源文章案例得到的規則

最早的編輯案例是一篇產品起源文章。文章有徵求約會影片、開放其他用途、動物園裡的大象等具體內容，但也反覆把「承認猜錯」「觀察使用者」「保持彈性」寫成不同段落，讓讀者一直往下讀，卻沒有得到新的理解。

這個案例提供四個可重用的判斷：

1. 先寫人物做了什麼，不先宣布這個決定後來多成功。
2. 讓具體行動和結果自己產生反差，不替讀者指定「這很感人」或「這很重要」。
3. 有畫面的口語例子不必概括成分類名稱。
4. 沒有新增資訊的作者旁白可以刪掉，直接接下一段。

產品案例只用來示範編輯方法。正式文章若涉及 YouTube 的日期、人物、收購、影片內容或產品歷史，仍要查核來源，不能把案例中的練習材料當成完整史實。

## v3 的核心設計

### 把規則放進真正會被讀取的範圍

公開 README、研究筆記與配圖可以說明專案，但安裝後真正會影響輸出的，是：

- SKILL.md：核心分流、執行順序、保留與改寫判斷、確定程度與交稿核對。
- references/style-profile.md：作者的穩定寫法，不搬用私人經歷。
- references/editing-examples.md：正反例與可能誤傷的情境。
- references/context-modes.md：不同用途的交付順序。
- references/protection-and-scenes.md：資訊、責任、條件與場景核對。
- references/youtube-case.md：完整案例。
- references/research-synthesis.md：研究來源與採用邊界。

研究摘要不能只放在 docs，否則安裝後的技能看不到它；但詳細來源也不應全部塞入 SKILL.md，否則核心流程會被研究筆記淹沒。

### 不把保留規則變成新的僵化模板

「自然原文保留」是防止過度改寫，不代表任何原文都不能動。v3 同時保留兩個方向：

- 原文已自然、清楚且符合用途：保留。
- 內容模糊、順序混亂、資訊被修飾遮住或不符合用途：局部修復或重寫。

新增每一條保留規則，都要附一個「應保留」案例和一個「確實要改」案例，避免修好過度改寫後，又變成完全不改。

## 評測設計

評測不計算「AI 味分數」，而是逐題核對：

- 事實、數字、URL、責任、限制與先後順序。
- 作者主張是否仍然存在，推論是否被誤寫成事實。
- 原文自然時是否被不必要地改寫。
- 空泛補句是否被替換成具體動作或下一步。
- 沒有來源的數字、結果、經歷與承諾是否被新增。
- 新寫、改稿、保留原文、只修標點與不同用途是否都能完成。

目前 repo 裡的早期題目可作為基線，但早期輸出有部分是在規則修改後手動調整的預期結果，不能直接視為新版本的實際通過。之後每次修改規則，都要：

1. 從原始 prompts 重新執行。
2. 保存原始輸出與執行版本。
3. 人工核對通過、失敗與尚未測試，不把預期輸出混進實際結果。
4. 增加一題可能誤傷的反例，確認新規則沒有造成過度保留或過度刪除。

## 版本邊界

這個技能可以保留、修復與重寫文字，但不會自行：

- 捏造作者經歷、客戶成果、研究數字或引用。
- 把案例中的品牌或人物搬到另一篇文章。
- 因為「像我」就加入私人資訊。
- 代替使用者寄出信件、發布內容或執行未授權操作。
- 用固定詞表判斷一句話一定是 AI 寫的。

版本 3.0.0 的目標，是讓技能重新記得自己的目的：先判斷，再動文字；先保住內容，再處理語氣。
